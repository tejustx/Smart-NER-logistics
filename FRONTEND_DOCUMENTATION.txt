1. FRONTEND OVERVIEW & DESIGN PHILOSOPHY
================================================================================
The frontend is engineered as a high-performance, zero-framework Single-Page
Application (SPA) designed to operate under low-bandwidth, high-latency, and
cellular dead-zone conditions across the North Eastern Region of India.

Core Design Tenets:
1. Zero Framework Overhead: Built with pure Vanilla JS (ES6+) and modern CSS3,
   achieving sub-50ms render times and eliminating large bundle dependencies.
2. Resilience First: All critical operational features (telemetry logging,
   manifest verification, checkpoint progression) execute locally when the
   driver enters mountain dead-zones.
3. Dual-Personality Visuals:
   - Himalayan Night-Ops (Dark Theme): High-contrast tactical HUD aesthetic
     using deep slates (#0a0f1d, #0f172a), glowing cyan/emerald vector trails,
     and pulsing radar alerts.
   - Quick-Commerce Daylight Mode (Light Theme): Crisp, elevated pure-white cards
     (#ffffff), soft off-white canvas (#f4f6f8), deep charcoal typography
     (#0f172a), and vibrant delivery accents inspired by Blinkit, Zepto,
     Zomato, and Swiggy.
4. Zero-Token Hardware-Accelerated 3D Mapping: MapLibre GL JS v4 renders
   vector lines, 3D terrain angles (45° pitch), and interactive popups with
   100% open-source CartoDB raster tiles requiring no third-party keys.

--------------------------------------------------------------------------------
4.2 HIMALAYAN NIGHT OPS DARK THEME
--------------------------------------------------------------------------------
Default system state (:root or data-theme="dark"):
- Tailored for low-light command center oversight and nighttime freight convoys.
- Deep space backgrounds (#0a0f1d, #0f172a) minimize eye fatigue.
- High-contrast luminescent vector paths: Glowing neon emerald (#10b981) for safe
  mountain passes; dashed rose (#f43f5e) for high-hazard alternatives.
- Pulsing radar rings for active landslide locations.

--------------------------------------------------------------------------------
4.3 ZERO-FOUT THEME INITIALIZATION & PERSISTENCE
--------------------------------------------------------------------------------
To guarantee zero Flash of Unstyled Theme (FOUT):
1. In <head>, an immediate blocking IIFE executes prior to DOM construction:
   <script>
     (function() {
       var savedTheme = localStorage.getItem('smart_ner_theme') || 'dark';
       document.documentElement.setAttribute('data-theme', savedTheme);
     })();
   </script>
2. setTheme(theme) synchronizes:
   - document.documentElement attribute: data-theme="light" | "dark"
   - localStorage: key 'smart_ner_theme'
   - Toggle button icons (☀️ / 🌙) and labels ("Light Mode" / "Dark Mode")
   - Active MapLibre GL JS tile layers.

6. MAPPING ENGINE: MAPLIBRE GL JS v4 ARCHITECTURE
================================================================================

--------------------------------------------------------------------------------
6.1 ZERO-TOKEN OPEN ARCHITECTURE
--------------------------------------------------------------------------------
The platform uses MapLibre GL JS v4 via official CDN:
  <link href="https://unpkg.com/maplibre-gl@4.7.1/dist/maplibre-gl.css" rel="stylesheet" />
  <script src="https://unpkg.com/maplibre-gl@4.7.1/dist/maplibre-gl.js"></script>

Requires zero API tokens, credit cards, or external accounts. All vector and raster
tiles are fetched directly from CartoDB's high-speed global tile mirrors.

--------------------------------------------------------------------------------
6.2 DUAL BASEMAP SYNCHRONIZATION
--------------------------------------------------------------------------------
Two independent raster tile styles are defined in frontend/js/app.js:

1. MAPLIBRE_DARK_STYLE:
   Uses CartoDB Dark Matter raster tiles:
   https://a.basemaps.cartocdn.com/dark_all/{z}/{x}/{y}@2x.png
   Designed for nighttime operations and high-contrast glowing HUD paths.

2. MAPLIBRE_LIGHT_STYLE:
   Uses CartoDB Voyager raster tiles:
   https://a.basemaps.cartocdn.com/rastertiles/voyager/{z}/{x}/{y}@2x.png
   Designed for clean, daylight operations with crisp road network contours.

Dynamic Switching:
When the user toggles the theme, setTheme() calls map.setStyle(newStyle). Upon
the map's 'load' event, route polylines and markers are re-rendered automatically.

--------------------------------------------------------------------------------
6.3 3D PERSPECTIVE CONTROLS
--------------------------------------------------------------------------------
Maps are initialized with native 3D perspective pitch and bearing:
- Route Map (#route-leaflet-map):
  center: [92.75, 26.65] (Brahmaputra Valley)
  zoom: 7.3
  pitch: 45° (3D mountain slope perspective)
  bearing: -12° (Oriented toward Arunachal Himalayan foothills)
- Regional Gov Map (#gov-leaflet-map):
  center: [93.0, 26.2]
  zoom: 6.6
  pitch: 40°
  bearing: -8°

Navigation Controls:
maplibregl.NavigationControl({ visualizePitch: true }) added to top-right corner.

--------------------------------------------------------------------------------
6.4 DYNAMIC VECTOR GEOJSON LAYERS (ROUTE A VS ROUTE B)
--------------------------------------------------------------------------------
In renderMapLibreRoutes(routes):
1. Coordinate Transposition:
   Converts backend [lat, lng] pairs to GeoJSON standard [lng, lat]:
   const coordsLngLat = r.path_coordinates.map(pt => [pt[1], pt[0]]);
2. Route B (Safe Corridor) Dual Layer:
   - Under-layer (Neon Glow):
     type: "line", line-color: "#10b981", line-width: 14, line-blur: 6, line-opacity: 0.35
   - Upper-layer (Solid Path):
     type: "line", line-color: "#10b981", line-width: 5, line-opacity: 0.95
3. Route A (High Hazard Corridor):
   - Dashed Red Line:
     type: "line", line-color: "#f43f5e", line-width: 3.5, line-dasharray: [2, 2]
4. Interactive Click Popups:
   Clicking any corridor displays risk score, duration, distance, and safety status.
5. Spatial Bounding Box Fitting:
   allLngLats.reduce((b, coord) => b.extend(coord), new maplibregl.LngLatBounds(...))
   map.fitBounds(bounds, { pitch: 45, bearing: -12, duration: 1600 })

8. OFFLINE-FIRST SYNCHRONIZATION ENGINE (OfflineSyncManager)
================================================================================
Defined in frontend/js/offline_sync.js:

Storage Keys:
- smart_ner_cached_trip: Complete trip JSON for offline driver navigation.
- smart_ner_offline_sync_queue: Write-Ahead-Log array of pending telemetry events.
- smart_ner_connectivity_mode: "Online" | "Offline".
- smart_ner_theme: "dark" | "light".

Execution Flow:
1. recordDriverAction({ type, payload }):
   - Creates action record:
     { id: "ACT-" + Date.now(), type: "CHECKPOINT"|"DELIVERY", payload, timestamp, offlineRecorded: !isOnline }
   - Appends to this.syncQueue in LocalStorage.
   - Optimistically mutates locally cached trip so driver sees instant UI green checkmark.
2. flushSyncQueue(apiBaseUrl):
   - Triggered upon network restoration or manual reconnection toggle.
   - Dispatches batch payload to POST /api/driver/sync-telemetry.
   - Upon receiving HTTP 200 { status: "SYNCED" }, clears LocalStorage queue.
